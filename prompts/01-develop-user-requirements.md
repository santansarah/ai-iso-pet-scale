# Task 1 — Develop the user requirements

> Help me develop a user requirements specification for my project, drawing on ISO/IEC/IEEE 29148 requirements-engineering principles.
>
> Use the attached example as a reference for structure, readability, and level of detail. Adapt it to my project rather than copying its assumptions or requirements.
>
> Start by understanding the product’s purpose, intended users, operating environment, scope, and constraints. Then walk through the user journey with me, asking one focused question at a time. Consider normal use, boundary conditions, failures, interruptions, cancellation, and recovery.
>
> We will examine hazards in a separate task using these requirements as input. During this task, capture potential safety concerns and unresolved questions for that review. Where a concern affects required behavior, discuss it with me before adding a requirement.
>
> Give each requirement a stable ID and each acceptance criterion its own ID. Write clear, observable outcomes that developers, AI agents, internal QA, and external testing teams can use to develop tests. Include user workflows and a traceability map linking workflows, requirements, and acceptance criteria.
>
> Distinguish confirmed decisions, proposals, and open questions. Separate required behavior from implementation choices, and document what is outside scope. Don’t invent missing decisions or claim ISO compliance.
>
> Review the content with me before finalizing. Check for ambiguity, contradictions, duplication, and missing scenarios. Format the result as an easy-to-follow document with clearly labeled IDs and readable tables.
